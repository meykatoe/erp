# 架構設計

## 總覽

```
瀏覽器 ──> Nginx (靜態檔 + /api 反向代理) ──> NestJS API ──> PostgreSQL
```

前端為單頁應用,所有資料透過 `/api` 取得。API 為無狀態服務,可水平擴充;
狀態只存在 PostgreSQL。

## 後端模組

| 模組 | 職責 |
| --- | --- |
| auth / users / roles | 登入、使用者、角色與權限 |
| audit | 寫入類請求的稽核紀錄 |
| sequence | 單據流水號,以資料庫計數器保證不重複 |
| products / categories / warehouses | 商品與倉庫主檔 |
| customers / suppliers | 往來對象 |
| purchase | 採購單狀態機、收貨 |
| sales | 銷售單狀態機、出貨、信用額度 |
| inventory | 庫存水位、異動、盤點、調撥 |
| accounting | 科目、傳票、發票、收付款、試算 |
| hr | 部門、員工、考勤、請假、薪資 |
| reports | 儀表板與統計查詢 |

## 設計原則

- 模組之間透過 service 介面溝通,不直接操作對方的資料表
- 跨表寫入一律在單一資料庫交易內完成
- 金額使用 `Decimal`,避免浮點誤差
- 單據狀態採明確狀態機,非法轉換直接拒絕
- 收貨、出貨會先鎖定單據列 (`SELECT ... FOR UPDATE`),避免並發重複過帳
- 所有寫入請求留稽核紀錄,密碼欄位會遮蔽

## 資料流範例: 採購收貨

1. 驗證單據狀態與未收數量
2. 重算商品移動平均成本
3. 增加庫存並寫入異動紀錄
4. 產生分錄: 借 存貨 / 貸 應付帳款
5. 建立應付帳款單,到期日依供應商付款天數計算
6. 更新單據狀態為部分收貨或已收貨

以上步驟同屬一個交易,任何一步失敗即全部回復。
